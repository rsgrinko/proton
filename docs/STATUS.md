## Что сделано последним заходом

1. **Перенос в свой репозиторий доведён.** После переноса не было `.env` (лежал
   рядом как `.env00`) — приложение считалось неустановленным, и семь HTTP-тестов
   падали. Конфиг восстановлен, прогон снова зелёный.

2. **TLS к чужим сервисам.** У PHP на машине разработки нет своего хранилища
   корневых сертификатов, из-за чего падала отправка через почтовый сервис
   («unable to get local issuer certificate»). Появился общий `Support\HttpClient`
   (curl с откатом на потоки) и настройки `HTTP_CA_BUNDLE`, `HTTP_TIMEOUT`,
   `HTTP_VERIFY_PEER`; на клиент переведён драйвер `mailer`, тот же набор
   сертификатов подхватывает SMTP. Проверку сертификата по умолчанию не отключаем.

3. **Вебхуки — второй пункт первой волны.** Подписки заводятся в панели (раздел
   «Вебхуки», право `webhooks.manage`): события галочками, секрет с заменой, пробная
   посылка, журнал доставок со страницами. Посылка подписывается HMAC-SHA256 от
   «время.тело», повторы ведёт очередь (тело берётся из журнала, поэтому подпись
   сходится), подписка после `WEBHOOKS_DISABLE_AFTER` неудач подряд отключается сама.
   События живут в коде: ядро — `user.*`, приложение — `config/webhooks.php`; реестр
   повешен на шину событий, поэтому достаточно `Events::fire()`. Заметки теперь
   объявляют `note.created|updated|deleted`. Воркер научился разбирать несколько
   очередей (`--queue=default,webhooks`). Команды: `webhook:list`, `webhook:test`.

   Проверено не только тестами: пробная и настоящая посылки дошли до локального
   приёмника, подпись сошлась, ответ 500 вернул посылку в очередь с паузой.

4. **Уведомления — вторая половина того же пункта.** `Notifications\Notify` рассылает
   по каналам: `database` — строка в ленте `/notifications` (своя у каждого, чужих
   не видно, счётчик непрочитанных в шапке), `mail` — письмо очередью общим шаблоном
   `mail/notification`. Уведомление — класс-наследник `Notification` (`type`, `title`,
   `body`, `url`, `channels`); адресата можно не перечислять, а указать право —
   `Notify::toPermission()`. Сорвавшийся канал не роняет вызвавший код, только лог.
   Первое уведомление ядра — `WebhookDisabledNotification`: подписка отключилась сама.
   Прочитанные старше `NOTIFICATIONS_KEEP_DAYS` убирает воркер, непрочитанные — нет.

   Попутно нашлось и починено: `Router::url()` вне запроса падал на «Неизвестный
   маршрут» (воркер и консоль маршруты не поднимают) — теперь роутер поднимается
   сам, `Router::boot()`, и появился `Router::absolute()` для ссылок в письмах.

   Проверено живьём: подписка на битый адрес отключилась, оба администратора
   получили уведомление в ленту и письмом, счётчик в шапке обнулился кнопкой
   «Прочитать всё».

5. **Настройки через панель.** Реестр настроек живёт в коде (`Support\Settings`,
   свои — в `config/settings.php`), в базе только значения под префиксом `config:`.
   Значение из базы ложится поверх `.env`, сброс — это удаление строки, иначе правка
   `.env` перестала бы что-то значить. Применяются один раз за процесс
   (`Settings::apply()` в ядре и консоли). Раздел «Настройки» в панели, право
   `settings.manage`, журнал на каждую правку (секреты в него не пишутся). В форме
   есть скрытый список показанных настроек: без него частичная форма сбрасывала бы
   галочки, которых в ней не было.

6. **Резервные копии.** SQLite — `VACUUM INTO`, MySQL — свой дамп на запросах, без
   `mysqldump` и `exec()`. Файл сжимается и сразу проверяется (`PRAGMA
   integrity_check` или разбор дампа); негодная копия не сохраняется. Ротация по
   `BACKUP_KEEP`, расписание по `BACKUP_SCHEDULE` (задача в очередь, о неудаче
   уведомление тем, у кого `system.manage`). Раздел «Копии» в панели: сделать,
   скачать, проверить, удалить. Восстановление — только из консоли с `--force`,
   перед заменой делается страховочная копия.

   По пути нашлось: имя копии с точностью до секунды давало совпадение, и
   страховочная копия затирала исходную — в имени появился случайный хвост.

## О чём помнить

- База считается боевой: ничего не удаляем и не затираем по своей инициативе. После
  проверок свои записи убираем точечно, по id.
- Тесты всегда идут на своей базе (`TEST_DB_*`), настройки `DB_*` раннер не читает.
- После выкладки кода воркер нужно перезапускать — он держит классы в памяти.
- Копии базы лежат в `var/backups` и в git не попадают. Перед рискованной правкой
  схемы стоит сделать `backup:create`.
- Обращения к чужим сервисам — только через `Support\HttpClient`, своих `curl_init`
  в коде быть не должно.
- Правила проекта, архитектура и соглашения — в `CLAUDE.md` в корне.

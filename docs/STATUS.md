## Что сделано последним заходом

1. **Баг при удалении пользователя.** `UsersController::delete(int $id, User $current)`
   падал ещё до тела метода: роутер подставляет аргументы по именам, а прослойка
   `Authenticate` кладёт в запрос `user`, `viewer`, `scope` — атрибута `current`
   нет. Аргумент переименован, удаляемый стал `$target`, на удаление написан тест.

2. **Фильтры и сортировка списков.** `Support\Filters` разбирает параметры адреса,
   подмешивает их в запрос и отдаёт вьюхе то, из чего рисуются форма (партиал
   `filters`), заголовки-ссылки (партиал `sort`) и ссылки страниц. Типы полей:
   поиск по нескольким колонкам, выбор из списка, точное совпадение, да/нет,
   заполнено/пусто, диапазон дат. Сортировка — только по белому списку колонок:
   имя уходит в `ORDER BY`. Негодное значение из адреса отбрасывается, а не роняет
   страницу. Переведены пользователи, журнал, ключи, вебхуки, заметки, уведомления.

   Попутно нашёлся баг ядра: `Builder::whereLike()` экранировал `%` и `_` обратным
   слэшем, но не добавлял `ESCAPE`, поэтому поиск по строке с подчёркиванием
   («qa_filters») не находил ничего. Теперь экранирование идёт восклицательным
   знаком вместе с `ESCAPE` — одинаково в SQLite и MySQL.

3. **Контейнер как у взрослых.** `bind`/`singleton`/`set`, интерфейс → класс,
   замыкание-сборщик, реестр в `config/services.php`, сборка аргументов метода
   (`call()`), понятное сообщение при нехватке аргумента и ловля колец
   зависимостей. Класс без привязки теперь собирается каждый раз заново, общими
   бывают только те, кого об этом попросили. Роутер собирает контейнером всё, что
   в действии имеет тип-класс и не пришло из адреса или атрибутов; модели
   контейнер не собирает вовсе.

4. **Выгрузка и загрузка списков.** `Support\Csv` (BOM, точка с запятой,
   обезвреженные формулы), `Support\Export` (тот же запрос, что на экране, порции
   по 500 строк, предел `EXPORT_MAX_ROWS`, запись в журнал), `Support\Import`
   (проверка каждой строки, отчёт с номерами, предел `IMPORT_MAX_ROWS`). Кнопка
   «Выгрузить CSV» — у пользователей, журнала и заметок; загрузка из файла —
   в заметках, как образец.

5. **Отчёты.** Раздел «Отчёты» (право `system.view`): регистрации, входы, заметки,
   посылки вебхуков рядами за неделю/месяц/три месяца/год, столбики без внешних
   библиотек, выгрузка ряда файлом. Считает `Support\Reports`: периоды без записей
   приходят нулями, неделя обозначается датой понедельника — номера недель у SQLite,
   MySQL и PHP разъезжаются на стыке годов.

6. **Показатели и присмотр.** Ядро пишет счётчики запросов (время ответа, 5xx,
   медленные) в кэш почасовыми ведёрками; снимок состояния считается из базы и
   отдаётся через `GET /api/v1/metrics` под ключом с правом `system.view`. Блок
   показателей появился на странице «Состояние». `Support\Monitor` из расписания
   сравнивает очередь, ошибки и место на диске с порогами `MONITOR_*` и уведомляет
   тех, у кого `system.manage`, не чаще раза в час на одну и ту же беду.

   Проверено не только тестами: фильтры, сортировка, выгрузка, загрузка файла
   и отчёты прогнаны в браузере на локальном сервере.

## О чём помнить

- База считается боевой: ничего не удаляем и не затираем по своей инициативе. После
  проверок свои записи убираем точечно, по id.
- Тесты всегда идут на своей базе (`TEST_DB_*`), настройки `DB_*` раннер не читает.
- После выкладки кода воркер нужно перезапускать — он держит классы в памяти.
- Копии базы лежат в `var/backups` и в git не попадают. Перед рискованной правкой
  схемы стоит сделать `backup:create`.
- Обращения к чужим сервисам — только через `Support\HttpClient`, своих `curl_init`
  в коде быть не должно.
- Правила проекта, архитектура и соглашения — в `CLAUDE.md` в корне.

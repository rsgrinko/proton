# Журнал изменений ядра

Версии — мажор.минор.патч, бампаются вручную (`php bin/proton core:bump`), не
на каждый коммит: запись размечает точку, к которой имеет смысл
синхронизировать другой проект, не сам коммит. `**Ломает:**` — синхронизация
не бесплатна, нужно что-то доделать руками на стороне проекта. Подробности
механизма — `docs/CORE_UPDATES.md`.

## 1.5.2
- Container: объект из set() до первого обращения не затирается привязками config/services.php

## 1.5.1
- Model\Query::pluck() отдаёт значения, а не падает на моделях: Builder::rows(), pluck() строится на нём

## 1.5.0
- HttpClient: свой файл корневых сертификатов у клиента третьим аргументом — для сервисов со своим УЦ (корень Минцифры), без установки сертификата в ОС

## 1.4.0
- HttpClient: прокси http/socks5 вторым аргументом, fake() со списком ответов и функцией; задачи очереди и команды собирает контейнер (зависимости в конструкторе); Settings::refresh() — воркер перед задачей и расписанием, демон перед кругом; Settings::FLOAT и Env::float(); Console\DaemonCommand и daemon:stop; Query\Builder::upsert() и whereDate()

## 1.3.0
- Models\Invitation — приглашения с ролью (миграция create_invitations, контроллеры и вьюхи — в скелете приложения); User::preloadAvatars() и currentAvatar(): аватары списка одним запросом; настройка auth.invite_days (AUTH_INVITE_DAYS)

## 1.2.0
- **Ломает:** пустой `$fillable` у модели теперь значит «ничего», а не «всё»:
  перечислить поля у своих моделей, иначе `create()`/`fill()`/`update()` их
  отбросят. Регистрация выдаёт роль из `AUTH_REGISTRATION_ROLE` (по умолчанию
  «Пользователь»); роли нет или в ней права на управление — регистрация закрыта.
  `can:` на API проверяет ключ, а не сессию — повесить `can:` на свои
  API-маршруты.
- Нельзя выдать больше своего: `Viewer::covers()`, `Role::assignableBy()` —
  роли, права ролей, правка и вход под пользователем, ключ на его имя.
- Недоступная база — 503, а не открытый `/install`; `DatabaseException`
  подключения несёт код `Connection::UNAVAILABLE`.
- `HttpClient` и правило `url` — только http/https.
- `Job::timeout()`; `releaseStuck()` хоронит задачу, исчерпавшую попытки, и
  зовёт `failed()`; расписание срабатывает и между задачами; по SIGTERM воркер
  не доразбирает очередь.
- `Query::remember()` со своим ключом держит варианты запроса (страницы) и
  кэширует пустой ответ.
- Кука токена форм подписана вместе с селектором «запомнить меня»; Referer в
  редиректе — только путь; `X-Forwarded-Proto` — только от `TRUSTED_PROXIES`.
- Меньше записей на запрос: опись устройств и ключ API — не чаще раза в минуту;
  `Metrics` под замком.

## 1.1.0
- **Ломает:** база `framework/.checksums.json` — суммы ядра (общий предок),
  а не снимок своего `framework/`. Проекту на 1.0.0: перенести
  `Core\Updater` и `framework/Console/` через `--path`, затем заново завести
  базу — `core:check --baseline --path=<ядро 1.0.0>`.
- `core:resolve <файл>` — отметить ручное слияние разобранным;
  `core:check --baseline --path=|--remote` — база от ядра.
- `core:sync --apply` сам ставит версию ядра, когда ручного слияния нет.
- `--remote` работает с GitHub (архив с codeload, без редиректа) и не
  зависит от `sys_temp_dir`.
- `core:bump` пишет запись над последней версией, а не над вводным абзацем.

## 1.0.0
- Начало версионирования ядра: `framework/VERSION`, `core:bump`,
  `Core\Updater` (контрольные суммы вместо археологии по git log),
  `core:version`/`core:check`/`core:diff`/`core:sync`/`core:latest`.
- Событие `http.responded` в `Kernel::handle()` — точка расширения вместо
  патча ядра для всего, что должно случиться после каждого ответа.
- Слоты каркаса `View::slot()`/`View::fillSlot()` — `layout.head`,
  `layout.topbar` в `layouts/main.php`.

# Быстрый старт

Нужен PHP 8.1 или новее с `pdo` (`pdo_sqlite` и/или `pdo_mysql`), `mbstring`,
`openssl`, `json`. Composer не нужен.

## Установка

Установщик пишет `.env`, создаёт ключ, накатывает схему и заводит администратора.
Дверей две — консоль и браузер, — а движок один (`Install\Installer`), поэтому
ставят они одинаково.

```bash
php bin/proton install
```

Команда спросит название, адрес, базу, почту, логин и пароль администратора. То же
можно передать сразу: `--name=`, `--url=`, `--db=sqlite|mysql`, `--admin=`,
`--admin-password=`. На установленном приложении повторный запуск ничего не трогает,
пока не сказано `--force`.

Через браузер:

```bash
php bin/proton serve --host=127.0.0.1 --port=8000
```

Порт занят — команда возьмёт следующий свободный и скажет какой. Останавливается
Ctrl+C.

Пока приложение не установлено, любой адрес уводит на `/install`. Мастер сначала
показывает проверки окружения (версия PHP, расширения, права на запись), потом
спрашивает то же, что консоль. Базы MySQL ещё нет — заведёт сам, если у пользователя
есть такое право. В конце вводит вас в панель администратором.

После этого установщик закрывается: `/install` уводит на главную.

Недоступная база установщик не открывает: `/install` и остальные страницы отвечают
503, пока она не вернётся. Иначе любой прохожий в момент сбоя MySQL переписал бы
`.env` на свою базу. Поправить настройки базы на уже установленном приложении —
`php bin/proton install --force` в консоли или правка `.env` руками.

Дальше пользователи заводятся в панели или командой:

```bash
php bin/proton user:create admin --email=admin@example.com
```

Пароль можно не задавать — команда придумает его и покажет один раз.

## Настройки

Всё в `.env`, значения по умолчанию — в `config/config.php`. Самое нужное:

| Переменная | Зачем |
|------------|-------|
| `APP_KEY` | подпись кук и шифрование секретов в базе |
| `APP_URL` | по нему собираются ссылки в письмах |
| `APP_DEBUG` | на бою `false`, иначе тексты ошибок видны посторонним |
| `DB_DRIVER` | `sqlite` (по умолчанию) или `mysql` |
| `MAIL_DRIVER` | `mail`, `smtp`, `mailer`, `log`, `null` |
| `AUTH_REGISTRATION` | открыта ли регистрация |
| `AUTH_VERIFY_EMAIL` | требовать ли подтверждение почты |
| `AUTH_REGISTRATION_ROLE` | роль для зарегистрировавшихся самих, по имени; с правами на управление регистрация закрывается |

Часть настроек правится из панели и ложится поверх `.env` — см.
[SETTINGS.md](SETTINGS.md).

`APP_KEY` на живом проекте менять нельзя: зашифрованные значения станут
нечитаемыми, а куки — недействительными. Поэтому `app:key` без `--force`
существующий ключ не перезаписывает.

## Переезд на MySQL

```dotenv
DB_DRIVER=mysql
DB_HOST=127.0.0.1
DB_DATABASE=proton
DB_USERNAME=proton
DB_PASSWORD=…
```

```bash
php bin/proton migrate
```

Код одинаковый для обеих баз: диалект знает `Connection`, а миграции пишутся
отвлечёнными типами.

## Свой раздел

Быстрый путь — генератор, он делает раздел целиком:

```bash
php bin/proton make:crud Article --fields="title:string:Заголовок,body:text:Текст,published:bool:Опубликована"
```

Дальше останется подключить напечатанные куски: маршруты, право, пункт меню. Руками
то же самое:

```bash
php bin/proton make:migration create_articles
php bin/proton make:model Article
php bin/proton make:controller Articles
```

Порядок такой: описать таблицу в миграции и накатить (`migrate`), перечислить в
модели `$fillable` и `$casts`, написать действия в контроллере (образец —
`app/Controllers/Web/NotesController.php`), добавить маршруты в `routes/web.php`,
права в `config/permissions.php`, шаблоны в `resources/views/articles/` и строку в
`config/menu.php`.

## Заметки

Демонстрационный раздел: `app/Models/Note.php`, контроллеры в
`app/Controllers/Web` и `app/Controllers/Api`, шаблоны `resources/views/notes/`,
миграция `20260912100100_create_notes.php`. В нём есть всё, что обычно нужно
разделу: список с поиском и страницами, форма, загрузка файла, мягкое удаление,
область видимости, журнал действий, API и события для вебхуков.

Если он не нужен, удаляется целиком: перечисленные файлы, маршруты `/notes` в
`routes/web.php` и `routes/api.php`, права `notes.*` в `config/permissions.php`,
события `note.*` в `config/webhooks.php`, пункт меню и задача
`app/Jobs/RebuildNoteSlugsJob.php`. Таблицу уберёт откат миграции или `DROP TABLE
notes`.

## Как проходит запрос

Точка входа одна — `public/index.php`; всё, что не файл на диске, идёт туда. Ядро
(`framework/Http/Kernel.php`) собирает роутер, накладывает настройки из панели,
прогоняет запрос через прослойки и превращает любое исключение в понятный ответ:
страницу для браузера, JSON для API.

Маршруты описаны в `routes/`, у каждого есть имя — адреса в коде и шаблонах строкой
не пишутся, только `View::route('notes.show', ['id' => 5])`. Контроллер получает
зависимости через конструктор (собирает контейнер), а аргументы действия — по
именам: `Request`, `{id}` из адреса, `Viewer` и `Scope` от прослойки авторизации.

Шаблоны — обычные PHP-файлы. Ищутся сначала в `resources/views`, потом в
`framework/View/views`, поэтому любой шаблон ядра перекрывается своим файлом с тем
же именем.

# Быстрый старт

## Что нужно

PHP 8.1 или новее с расширениями `pdo` (`pdo_sqlite` и/или `pdo_mysql`), `mbstring`,
`openssl`, `json`. Composer не нужен и не используется.

## Установка

Ставит приложение установщик: он пишет `.env`, создаёт ключ, накатывает схему и
заводит администратора. Две двери, движок один (`Install\Installer`) — консоль и веб
ставят систему одинаково.

Из консоли:

```bash
php bin/proton install
```

Команда спросит название, адрес, базу, почту и логин с паролем администратора.
Всё то же можно передать сразу: `--name=`, `--url=`, `--db=sqlite|mysql`, `--admin=`,
`--admin-password=`. Повторный запуск на установленном приложении ничего не трогает,
пока не сказано `--force`.

Через браузер:

```bash
php bin/proton serve --host=127.0.0.1 --port=8000
```

Порт занят — команда возьмёт следующий свободный и скажет об этом. Останавливается Ctrl+C.
Любой адрес неустановленного приложения уводит на `/install`: мастер сначала показывает
проверки окружения (версия PHP, расширения, права на запись), потом спрашивает то же
самое, что и консоль. Базы MySQL ещё нет — установщик заведёт её сам, если у пользователя
есть на это право. В конце он сам вводит вас в панель администратором.

Как только пользователь заведён, установщик закрывается: `/install` уводит на главную.
Отдельной страницы первого запуска нет — дверь одна.

Дальше пользователи заводятся в панели или командой:

```bash
php bin/proton user:create admin --email=admin@example.com
```

Пароль можно не задавать — команда придумает его и покажет один раз.

## Настройки

Всё живёт в `.env` (значения по умолчанию — в `config/config.php`). Главное:

| Переменная | Зачем |
|------------|-------|
| `APP_KEY` | подпись кук и шифрование секретов в базе. Без него не работают подписанные куки |
| `APP_URL` | адрес приложения: по нему собираются ссылки в письмах |
| `APP_DEBUG` | на бою `false`: иначе тексты ошибок видны посторонним |
| `DB_DRIVER` | `sqlite` (по умолчанию) или `mysql` |
| `MAIL_DRIVER` | `mail`, `smtp`, `mailer`, `log`, `null` |
| `AUTH_REGISTRATION` | открыта ли регистрация |
| `AUTH_VERIFY_EMAIL` | требовать ли подтверждение почты |

Менять `APP_KEY` на живом проекте нельзя: зашифрованные значения станут нечитаемыми,
а все куки — недействительными. Команда `app:key` без `--force` существующий ключ не трогает.

## Переезд на MySQL

```env
DB_DRIVER=mysql
DB_HOST=127.0.0.1
DB_DATABASE=proton
DB_USERNAME=proton
DB_PASSWORD=…
```

```bash
php bin/proton migrate
```

Один и тот же код работает на обеих базах: диалект знает `Connection`, а миграции
пишутся отвлечёнными типами.

## Свой первый раздел

```bash
php bin/proton make:migration create_articles
php bin/proton make:model Article
php bin/proton make:controller Articles
```

1. В миграции опишите таблицу и накатите её: `php bin/proton migrate`.
2. В модели перечислите `$fillable` и `$casts`.
3. В контроллере напишите действия, взяв за образец `app/Controllers/Web/NotesController.php`.
4. Добавьте маршруты в `routes/web.php` и права в `config/permissions.php`.
5. Положите шаблоны в `resources/views/articles/`.
6. Пункт меню — строка в `config/menu.php`.

## Демонстрационный раздел

Заметки (`app/Models/Note.php`, `app/Controllers/Web/NotesController.php`,
`app/Controllers/Api/NotesController.php`, `resources/views/notes/`,
`migrations/20260912100100_create_notes.php`) — образец на всех слоях: список
с поиском и страницами, форма, загрузка файла, мягкое удаление, область видимости,
журнал действий и API.

Он не нужен — удаляется целиком: перечисленные файлы, маршруты `/notes` в
`routes/web.php` и `routes/api.php`, права `notes.*` в `config/permissions.php`,
пункт меню и задача `app/Jobs/RebuildNoteSlugsJob.php`. Таблицу уберёт откат
её миграции либо просто `DROP TABLE notes`.

## Как устроено приложение

- **Точка входа одна** — `public/index.php`. Всё, что не файл на диске, идёт туда.
- **Ядро** (`framework/Http/Kernel.php`) собирает роутер, прогоняет запрос через
  прослойки и превращает любое исключение в понятный ответ: страницу для браузера,
  JSON — для API.
- **Маршруты** описаны в `routes/`, у каждого есть имя. Адреса в коде и шаблонах
  не пишутся строкой: `View::route('notes.show', ['id' => 5])`.
- **Контроллеры** получают зависимости через конструктор (их собирает контейнер),
  а аргументы действий — по именам: `Request`, `{id}` из адреса, `user`, `viewer`,
  `scope` от прослойки авторизации.
- **Модели** — Active Record поверх своего построителя запросов.
- **Шаблоны** — обычные PHP-файлы: сначала ищутся в `resources/views`, потом в
  `framework/View/views`. Любой шаблон ядра перекрывается своим файлом с тем же именем.
